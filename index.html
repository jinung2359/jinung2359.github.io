01채팅 실패를 재연결 안내로 연결하기
문제

채팅 전송에 실패해도 연결 종료 이벤트만으로 오류를 알리지 못하는 경우가 있었습니다. 평가 진행률 전송과 초기 미디어 연결 협상이 겹치는 상황도 다뤘습니다.

구현

채팅의 연결 상태 오류를 화상방에 전달해 재연결 안내를 표시했습니다. 전송 실패 시 입력 내용을 복원하고, 평가 진행률은 1.5초 지연과 타이머 정리로 연속 변경을 묶었습니다.

달라진 동작

채팅 전송 실패에서도 복구 경로를 안내하고, 평가 진행률의 즉시 반복 전송을 줄이는 구조로 변경했습니다.

02이미지 하나의 오류가 로그아웃으로 번지지 않도록
문제

보호된 이미지의 401 응답이 전역 인증 만료 이벤트를 발생시켜, 이미지 로딩 실패가 전체 로그아웃으로 이어졌습니다.

구현

이미지 요청 경로에서 전역 인증 만료 이벤트를 제거했습니다. 이미지 오류는 해당 요청에서 처리하고 일반 데이터 API의 세션 만료 판단은 유지했습니다.

달라진 동작

이미지 요청의 401 응답이 직접 전체 로그아웃을 유발하지 않도록 오류의 영향 범위를 분리했습니다.

03미리 받은 목록에서, 서버 기준 검색으로
문제

최대 100개를 먼저 받은 뒤 화면에서 검색·필터링해, 조회 범위 밖의 스터디까지 검색 결과에 반영하기 어려운 구조였습니다.

구현

검색어·모집 상태·정렬을 서버에 전달하고 6개씩 조회하도록 변경했습니다. 검색어에는 300ms 디바운스를 적용하고 조건 변경 시 첫 페이지부터 조회했습니다.

달라진 동작

전체 건수와 마지막 페이지 여부를 서버 응답으로 표시하고, 더보기에서 다음 페이지를 요청하도록 전환했습니다.

PROBLEM SOLVING
01늦게 도착한 인증 응답도 현재 세션인지 확인하기
고려한 상황

토큰 재발급을 기다리는 사이 로그아웃하면, 뒤늦은 응답을 그대로 저장하지 않도록 해야 합니다. 여러 화면에서 세션 만료를 일관되게 처리하는 흐름도 필요했습니다.

구현

세션 상태와 버전을 관리하는 서비스를 추가했습니다. 재발급 시작 시의 버전을 토큰 저장 전후에 확인하고, 만료 시 토큰 정리와 구독자 알림을 공통 처리했습니다.

달라진 동작

재발급 결과를 적용하기 전에 세션을 확인하는 단계를 추가하고, 이미 만료된 상태의 중복 알림을 제어했습니다.

02진단에서 상담으로, 맥락이 섞이지 않게
문제

특정 금융 진단에서 상담으로 진입할 때 일반 상담의 이전 대화를 재사용하면 다른 항목의 내용이 섞일 수 있었습니다.

구현

진단 상담과 일반 상담의 캐시를 분리했습니다. 진단 식별자로 첫 조언 요청의 중복 실행을 제어하고, 후속 요청에도 맥락을 전달하도록 구성했습니다.

달라진 동작

진단 상세에서 첫 조언을 바로 요청하고, 새로운 대화 ID가 반환되면 이전 대화 표시를 정리하도록 했습니다.

03관리 점수와 실제 비율을 명확하게 구분하기
문제

금융 효율의 관리 점수와 또래 비교의 실제 비율은 의미가 다릅니다. 짧은 항목명과 숫자만으로는 같은 지표로 오해할 여지가 있었습니다.

구현

‘지출 관리 점수’처럼 라벨을 구체화하고 월간 지표에 기준 기간을 표시했습니다. 응답 매핑과 타입·컴포넌트를 수정하고, 데이터 부족 안내를 분리했습니다.

달라진 동작

수치의 의미와 기준 기간을 화면에 표시하고, 계산할 데이터가 없는 상태를 실제 점수와 구분했습니다.
